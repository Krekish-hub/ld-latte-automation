# Приложение заявок

React + TypeScript + Vite, Supabase Auth/Data API. Опубликованный адрес: https://latte.193-232-88-121.nip.io/.

## Локальный запуск

Требуется Node.js 22.12+ или 24 и pnpm. Использованный lockfile создан pnpm 11; зависимости зафиксированы в pnpm-lock.yaml.

1. Применить SQL и настроить Auth по [SUPABASE_SETUP.md](../../docs/SUPABASE_SETUP.md).
2. Скопировать .env.example в .env.local и вписать URL/publishable key своего проекта. Не помещать сюда DB password, JWT пользователей или secret/service_role key.
3. Из apps/web выполнить:

```sh
pnpm install --frozen-lockfile
pnpm dev
```

## Проверки и сборка

```sh
pnpm test
pnpm test:sql
pnpm test:ui
pnpm build
```

Для UI-теста требуется Chromium Playwright: установите `pnpm exec playwright install chromium`, если браузера ещё нет. Можно передать PLAYWRIGHT_EXECUTABLE_PATH для уже установленного Chromium. По умолчанию тест сам запускает локальный preview на 5190 и закрывает его; TEST_BASE_URL позволяет использовать существующий preview. Снимки сохраняются в игнорируемый tmp/qa.

Unit-тесты проверяют валидацию, буквальный поиск и сравнение повторного создания. SQL-тест запускает PostgreSQL/WASM PGlite с минимальной моделью Auth, применяет реальную миграцию и проверяет A/B/anon, ограничения, grants, RLS и rollback. Он выполняется дважды: с имитацией автоматического включения RLS и без неё. UI-тесты используют **подменённый API и вымышленные записи**, не проверяют живой Supabase и доставку писем.

Перед сдачей отдельно требуется проверка реальной регистрации, двух живых пользователей и прямых Data API-запросов в проекте Supabase. Успех локальных тестов её не заменяет.

`pnpm build` создаёт только статические файлы dist. Публикация не требует Node.js на VPS. VITE_* встраиваются в JS и являются публичной конфигурацией.

## Поведение

- Регистрация email/password, вход, выход; ожидание подтверждения, если оно включено в Supabase.
- Собственные заявки: создать, открыть, изменить текст/категорию/статус.
- Поиск по названию и фильтр статуса работают вместе, по 20 строк на страницу.
- Новая запись не отправляет owner/status/dates: defaults и RLS задаются БД.
- Синхронная блокировка submit, один UUID на попытку; повторный конфликт читается и сравнивается перед признанием успеха.
- Сохранение изменения фильтруется по исходному updated_at. Конфликт не объявляется успехом.
- Ошибка не очищает текст формы; состояния пустого списка и сбоя различаются.
- Смена аккаунта перемонтирует рабочее пространство, запросы списка отменяются.

## Ограничения текущего этапа

- Custom SMTP и доставка подтверждения ещё требуют настройки/живой проверки. Подтверждение email не отключалось приложением.
- Сохранение черновика после закрытия браузера, восстановление пароля, удаление заявок и админка не реализованы; последнее не требуется заданием.
- Схема DTO описана TypeScript-типами вручную; автоматическая генерация из схемы пока не подключена.
- Один внешний шрифт Google Fonts, при недоступности используется системный sans-serif.
- Telegram и документ исследования Instagram - отдельные этапы, их готовность не следует из готовности frontend.
