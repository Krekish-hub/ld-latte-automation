# План и предварительная архитектура

## Границы

1. Telegram: реально работающий n8n workflow и экспорт без секретов.
2. Instagram: исследование и план, без реализации и реальных доступов.
3. Заявки: работающее опубликованное приложение, исходники и воспроизводимая настройка Supabase.

## Предварительные решения

Веб: React + TypeScript + Vite, Supabase JS, CSS для адаптивного интерфейса. Отдельный прикладной сервер для этого объёма не нужен. Конкретные версии зависимостей выбираются и проверяются перед реализацией.

Supabase Auth обслуживает email/password. Таблица requests: UUID id, user_id, title, description, category, status, created_at, updated_at. В БД обязательность и непустые строки, ограничения значений категорий и статусов, default статуса new. RLS проверяет auth.uid() = user_id при чтении и изменении, включая WITH CHECK для запрета подмены владельца. В браузере только publishable/anon key; service_role там недопустим.

Список заявок с поиском по названию и фильтром статуса. Создание/редактирование через форму с валидацией; синхронная блокировка повторного submit до завершения запроса, понятные состояния загрузки, успеха и ошибки. Правило RLS проверяется прямыми запросами двух пользователей, отдельно от UI.

Telegram: источник services(id, name, active), предварительно Supabase/Postgres, окончательный выбор после уточнения доступов. /start каждый раз читает активные записи и динамически строит inline_keyboard. Callback содержит стабильный ID, обработчик повторно читает запись и отвечает текущим названием. Удалённая или отключённая услуга в старом меню обрабатывается понятным сообщением. Пустой список и сбой источника различаются. Секреты в n8n credentials.

Instagram: отдельный документ на основании актуальной официальной документации Meta. Сначала выбор поддерживаемого способа авторизации, затем роли/разрешения/токены, каталог метрик и ограничений, регулярный сбор, диагностика. Конкретные разрешения и сроки токенов до исследования не фиксируются.

## Ветки и порядок

- main: общая база и проверенные результаты.
- feat/telegram-n8n: задача 1.
- docs/instagram-plan: задача 2.
- feat/requests-app: задача 3, включая миграции и проверки.

Сначала общий репозиторий и документация, затем ветки от общей базы. Изменения компонентов независимы; общие документы интегрируются последовательно. Отдельная develop для такого объёма не требуется.

## Приёмка

- Бот: 0, 2, 5, 9 активных услуг; добавление, переименование, отключение без правки workflow; разные callbacks; устаревшие кнопки; импорт экспорта.
- Instagram: схема от владельца аккаунта до хранилища, роли владельца/техника/автоматики, таблица метрик с условиями и ссылками, проверки этапов, вопросы компании.
- Веб: регистрация/вход/выход; обязательные поля; создание, редактирование, три статуса; поиск и фильтр; обновление страницы и повторный вход; два пользователя и прямые запросы к чужим данным; узкий экран; ошибка сохранения; повторное нажатие.
- Сдача: доступные ссылки на приложение и репозиторий; инструкции Supabase/n8n; AI-журнал с реальными проблемами и проверками; известные ограничения.
