# Метрики, способы получения и ограничения

Проверено 30.10.2026 по официальным references [Instagram Account Insights](https://developers.facebook.com/documentation/instagram-platform/api-reference/instagram-user/insights), [Instagram Media Insights](https://developers.facebook.com/documentation/instagram-platform/reference/instagram-media/insights), [IG User](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-user) и [общему Insights guide](https://developers.facebook.com/documentation/instagram-platform/insights). Здесь описана доступность по документации, а не проверка аккаунта компании.

## Обязательные показатели

`HOST` зависит от способа подключения: Unified/Facebook → `graph.facebook.com`, Instagram Login → `graph.instagram.com`. Вызовы фиксируют версию; reference сейчас указывает v26.0. Общие permissions перечислены в [README](README.md#1-выбор-способа-подключения); любой read должен относиться к активу, на который владелец предоставил доступ.

| Бизнес-показатель | Получение | Период / параметры | Условия и ограничения |
|---|---|---|---|
| Текущее число подписчиков | `GET /{IG_ACCOUNT_ID}?fields=followers_count` | Снимок на момент чтения, своё `fetched_at` | Поле **followers_count** из IG User, с `s`. Не путать с insights `follower_count` или числом новых подписок. Историю строим ежедневными снимками; API-поле не возвращает прошлое число по произвольной дате. [IG User](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-user) |
| Подписки / отписки за период, дополнительно | `GET /{IG_ACCOUNT_ID}/insights?metric=follows_and_unfollows` | `period=day`, `metric_type=total_value`, `breakdown=follow_type`, since/until | Reference: не возвращается при <100 followers. Это потоки изменений, не текущий размер аудитории. Не подменяет `followers_count`. [Account Insights](https://developers.facebook.com/documentation/instagram-platform/api-reference/instagram-user/insights) |
| Просмотры контента аккаунта | `GET /{IG_ACCOUNT_ID}/insights?metric=views` | `period=day`, `metric_type=total_value`, since/until; при необходимости `follower_type` или `media_product_type` | Количество воспроизведений/показов, не уникальные люди. Метрика обозначена Meta как in development. Проверить продуктовый разрез отдельно; не объединять несовместимые breakdown в один запрос. [Account Insights](https://developers.facebook.com/documentation/instagram-platform/api-reference/instagram-user/insights) |
| Охват аккаунта | `GET /{IG_ACCOUNT_ID}/insights?metric=reach` | `period=day`; `total_value` или `time_series`; since/until; допустимы `media_product_type`, `follow_type` | Уникальные аккаунты, увидевшие контент, включая рекламу; оценочная метрика. Месячный уникальный охват запрашивать за нужный диапазон и сверить семантику ответа, не суммировать ежедневные значения. [Account Insights](https://developers.facebook.com/documentation/instagram-platform/api-reference/instagram-user/insights) |
| Просмотры отдельной публикации / Reel / Story | `GET /{IG_MEDIA_ID}/insights?metric=views` | Снимок media Insights; response period — lifetime; не назначаем дневные интервалы из account API | FEED, REELS, STORY. Обычный views относится к Instagram media и не включает взаимодействия на рекламе с этим media. Для Story действует 24-часовое окно. [Media Insights](https://developers.facebook.com/documentation/instagram-platform/reference/instagram-media/insights) |
| Охват отдельной публикации / Reel / Story | `GET /{IG_MEDIA_ID}/insights?metric=reach` | Lifetime-значение на момент чтения | FEED, REELS, STORY; оценка уникальных пользователей. Нельзя суммировать охват нескольких публикаций как уникальный охват аккаунта. [Media Insights](https://developers.facebook.com/documentation/instagram-platform/reference/instagram-media/insights) |
| Показатели взаимодействий публикации | Тот же media endpoint: `likes,comments,saved,shares,total_interactions` | Lifetime-снимки, допустимые метрики выбираем по media_product_type | `likes/comments/saved`: FEED, REELS. `shares/total_interactions`: FEED, REELS, STORY. Удалённые реакции могут уменьшать итог; не считать все ряды монотонными. Не запрашиваем все метрики для всех типов без capability matrix. [Media Insights](https://developers.facebook.com/documentation/instagram-platform/reference/instagram-media/insights) |

## Полезные дополнительные показатели

| Показатель | Как получить | Границы |
|---|---|---|
| Время просмотра Reels | media Insights: `ig_reels_avg_watch_time`, `ig_reels_video_view_total_time` | Только REELS; единицы и текущую трактовку сверить в ответе/reference перед включением в отчёт |
| Действия в Stories | media Insights: `navigation`, breakdown `story_navigation_action_type` | Только STORY; суммарные действия и разрезы forward/back/exit/next не равны просмотрам |
| Переходы по ссылке Story | media Insights: `link_clicks` | Только STORY; соблюдать короткое окно доступности |
| Рекламные/совокупные показатели media | `total_views,total_likes,total_comments` | Reference явно разрешает только Instagram API with Facebook Login; `total_views` может включать Facebook. Для Unified/Instagram Login в этом плане не обещаны |
| Демография | account Insights: `follower_demographics`, `engaged_audience_demographics` | Не входит в обязательный объём; пороги аудитории/взаимодействий, top-45, свой timeframe. У reference есть устаревшие примеры timeframe: до внедрения проверяем отдельно, не используем их как готовую спецификацию |

Источник дополнительной таблицы: [Media reference](https://developers.facebook.com/documentation/instagram-platform/reference/instagram-media/insights), [Account reference](https://developers.facebook.com/documentation/instagram-platform/api-reference/instagram-user/insights).

## Временные окна и качество

- Account/user metrics хранятся **до 90 дней** по [Insights guide](https://developers.facebook.com/documentation/instagram-platform/insights). Это горизонт доступной истории, а не разрешение запросить любые 90 дней одним вызовом. `since/until` передаём явно и пилотом проверяем допустимый размер интервала для каждой метрики. Reference описывает range как inclusive; на границах повторных выгрузок нужна дедупликация.
- Account reference использует `period=day` для views/reach; это не число дней хранения. `total_value` — агрегат выбранного диапазона, `time_series` — ряд. Их не складываем между собой. Без since/until API смотрит назад на 24 часа; для отчётности такое неявное окно не подходит.
- Media metrics хранятся **до 2 лет**. У Stories отдельное ограничение: **24 часа**; возможность отдельных webhook/highlight-ответов после истечения не является гарантией восстановления всей истории. Live video доступно только во время трансляции. [Media reference](https://developers.facebook.com/documentation/instagram-platform/reference/instagram-media/insights), [guide](https://developers.facebook.com/documentation/instagram-platform/insights).
- Meta допускает задержку расчёта **до 48 часов**. Разделяем предварительный и повторно прочитанный результат, сохраняем fetched_at и пересчитываем свежие окна. Доступность Story и задержка расчёта — разные ограничения; не обещаем окончательный Story-итог через 48 часов. [Account](https://developers.facebook.com/documentation/instagram-platform/api-reference/instagram-user/insights), [Media](https://developers.facebook.com/documentation/instagram-platform/reference/instagram-media/insights).
- Пустые/недоступные данные не записываем нулём. Некоторые account-метрики имеют порог 100 followers. Конкретно insights `follower_count` и `online_followers` ограничены этим порогом; в текущей interaction-таблице `follower_count` не дан как отдельная готовая строка параметров. Поэтому обязательное текущее число подписчиков берём через поле **followers_count**, без предположения о тождественности двух имён. [Account reference](https://developers.facebook.com/documentation/instagram-platform/api-reference/instagram-user/insights).
- Insights не возвращается для отдельных детей carousel/album: используем родительский media ID. Story-метрики с числом зрителей <5 могут возвращать ошибку 10. Для Story replies есть региональные исключения Europe/Japan; нулевой replies там не доказывает отсутствие ответов. [Media reference](https://developers.facebook.com/documentation/instagram-platform/reference/instagram-media/insights).
- `story_insights` webhook документирован только для Facebook Login; Instagram Login Insights webhook не поддерживается. Поддержку такого события у Unified этот план не утверждает: основа сбора — polling. [Insights](https://developers.facebook.com/documentation/instagram-platform/insights), [Media reference](https://developers.facebook.com/documentation/instagram-platform/reference/instagram-media/insights).

## Старые названия и расхождения источников

Account `impressions` deprecated для v22.0 и всех версий с 21.04.2025; вместо него выбран views. Media reference сохраняет оговорку о старых media до 02.07.2024, но она не основание строить новую систему на impressions. Общий guide ещё содержит старые примеры `impressions/profile_views/engagement`; их не копируем в рабочую конфигурацию. [Account reference](https://developers.facebook.com/documentation/instagram-platform/api-reference/instagram-user/insights), [Media reference](https://developers.facebook.com/documentation/instagram-platform/reference/instagram-media/insights).

Есть и расхождения параметров внутри Account reference: intro пишет `follower_type` для views, общая таблица параметров перечисляет `follow_type`, а строки отдельных метрик различаются. Используем **метрико-специфическую** строку таблицы и отдельный пилотный запрос. Начальный обязательный сбор не требует этих breakdown. Media reference перечисляет несколько period-параметров, но описание response говорит о lifetime: для MVP не обещаем дневную историю публикации по этому endpoint, храним lifetime-снимки. Эти замечания — ограничения документации, а не найденные ошибки живого API.

Перед внедрением таблица превращается в проверяемый каталог `(login_path, api_version, media_product_type, metric, params)`: результаты пилота и дата проверки прикладываются к каждой используемой комбинации. Отсутствие доступа или метрики отмечается как ограничение отчёта и согласуется с аналитиком.
