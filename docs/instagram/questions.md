# Что спросить у LD LATTE до внедрения

Реальные доступы для выполнения тестового не нужны. Следующие вопросы предназначены для будущего внедрения; пароли и токены не запрашиваются в письме/мессенджере.

## Аккаунты и владельцы

1. Сколько Instagram-аккаунтов, какие usernames и типы: Business, Creator, Personal? Когда переводились в professional?
2. Кому принадлежат активы, есть ли business portfolio, сколько их и кто может выбирать/передавать Instagram-активы приложению? Есть ли согласованный резервный администратор?
3. Есть ли связанные Facebook Pages и действующие Page tasks у владельца? Это нужно только при выборе Page-linked пути.
4. Кто сможет пройти OAuth, подтвердить business ownership/verification при необходимости и восстановить доступ после отзыва/смены portfolio?
5. У всех ли аккаунтов достаточно аудитории для нужных пороговых метрик? Есть ли особенности региона, ограничения/блокировки аккаунтов?

## Данные и отчётность

6. «Подписчики» — текущее число, ежедневный прирост, новые подписки/отписки или всё перечисленное?
7. «Просмотры» — views аккаунта, публикаций, Reels, Stories? Нужны Instagram-only, органика, boosted/ads, Facebook crossposting? В каких разрезах?
8. «Охват» нужен дневной, за диапазон, по публикации или по аккаунту? Нужна ли уникальность аудитории компании между аккаунтами? Последнее нельзя получить простым суммированием reach.
9. Какие метрики публикаций обязательны: likes/comments/saved/shares, total_interactions, watch time, Stories navigation/link_clicks? Список согласовать по типам media.
10. Какую историческую глубину ожидают? Есть ли существующие экспорты для периодов, недоступных API? Согласны ли с отдельным коротким окном Stories и риском неполноты?
11. Какая частота и допустимая задержка; какой часовой пояс и границы отчётного дня? Как показывать пересчитанные значения и unavailable?
12. Куда сохранять: PostgreSQL, Sheets, BI, другая система? Какие поля/ID и формат импорта она принимает? Кто отвечает за модель и сверку с нативным Insights?
13. Как долго хранить данные/сырые ответы и кто может их читать? Что делать с данными после отключения аккаунта?

## Приложение и эксплуатация

14. Есть ли Meta developer app, кому принадлежит, какие use cases/login setup/permissions/Advanced Access/Live mode уже оформлены? Доступен ли новый Unified setup?
15. Это строго внутренний сбор своих активов или сервис для внешних клиентов? От этого зависит review и access level.
16. Есть ли контролируемый HTTPS-домен, callback/webhook endpoint, server-side runtime, менеджер секретов и outbound-доступ к Meta? Кто выдаёт минимальные технические роли?
17. Кто принимает решение по обязательным правам login-конфигурации, в частности messaging в default Unified setup, если задача только про статистику?
18. Нужны ли рекламные total-метрики, которые reference сейчас относит только к Facebook Login? Это может изменить основной login path.
19. Кто получает оповещения об истечении/отзыве токена, неполных данных, неуспешном запуске? Как быстро владелец может переподключить аккаунт?
20. Какой бюджет и ожидаемый рост числа аккаунтов; где запускается scheduler и кто отвечает за backup, обновление API version и повторную проверку каталога метрик?

После ответов фиксируем один login path на каждое соединение, матрицу прав, пилотный аккаунт, принимаемый каталог метрик и критерии из [плана проверки](verification.md). При необходимости запрашиваем приглашения в кабинеты/роли, а секреты вводятся владельцем или через утверждённый менеджер секретов.
