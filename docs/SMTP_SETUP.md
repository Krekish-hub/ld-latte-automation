Пользователь выбрал подтверждение email; отключать его для обхода почтовой настройки не планируется. Настройки задаются владельцем непосредственно в Supabase Dashboard. Секретные пароли не включаются в Git и не пересылаются в чат.

## 2. Пример с почтой Mail.ru/list.ru

Можно использовать существующий ящик без покупки домена. Для тестового небольшого объёма нужен отдельный пароль приложения с правом **только отправки писем**, а не основной пароль почты.

1. Войти в свой почтовый ящик.
2. Настройки -> Все настройки -> Безопасность -> Пароли для внешних приложений.
3. Создать пароль с названием `LD LATTE Supabase`, выбрать **Только отправка писем в Почте**. Выполнить подтверждения владельца, если запрошены.
4. Ввести полученный пароль непосредственно в Supabase SMTP settings и сохранить у себя. В чат или на скриншот пароль не помещать.

Официальная инструкция и параметры: [Mail: вход из почтовых программ](https://help.mail.ru/mail/login/mailer/), проверено 30.10.2026.

## 3. Поля Supabase

Открыть Authentication -> Email/SMTP Settings и включить custom SMTP. Названия разделов могут различаться в версии Dashboard.

| Поле | Значение |
|---|---|
| Sender email | полный адрес своего ящика |
| Sender name | LD LATTE |
| Host | smtp.mail.ru |
| Port | 465 |
| Username | тот же полный адрес своего ящика |
| Password | отдельный пароль приложения, только в Dashboard |
| Encryption, если есть отдельный выбор | SSL/TLS |

Подтверждение email оставить включённым. Не использовать выдуманный адрес отправителя или домен nip.io как почтовый домен. При сохранении убедиться, что изменения действительно применились.

Supabase поддерживает custom SMTP; сервер отправляет письма от настроенного отправителя. Это передаёт SMTP credential Supabase для отправки писем, поэтому пароль должен иметь минимальное право отправки. Источник: [Supabase SMTP](https://supabase.com/docs/guides/auth/auth-smtp).

## 4. Проверка

1. Открыть /register опубликованного приложения, зарегистрировать свой тестовый адрес.
2. Получить письмо, проверить папку «Спам», перейти по ссылке и убедиться, что возврат ведёт на опубликованный сайт, а не localhost.
3. Войти, создать заявку, перезагрузить страницу, выйти и войти снова.
4. Повторить регистрацию на втором тестовом адресе, затем проверить изоляцию A/B по SUPABASE_SETUP.md.
5. При сбое сохранить код/текст ошибки из Auth logs без паролей и ссылок подтверждения. Проверить host/port, совпадение sender и username, право SMTP-пароля, подтверждение email, лимиты Supabase и почтового провайдера.

Статус: инструкция подготовлена; credential ещё не настроен и доставка не подтверждена. Отправка реального письма будет доказательством работоспособности, а не само сохранение формы.
