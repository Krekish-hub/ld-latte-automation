## Короткие ответы на возможные вопросы

**Откуда берутся услуги?** Из `public.services`: UUID, название, активность, порядок. Роль n8n имеет только чтение активных услуг. Доступа к заявкам и пользователям у неё нет. В репозитории есть повторяемые наборы 0/2/5/9 и примеры изменений.

**Почему отдельный узел отправки?** Нативный fixed collection редактора n8n превращал динамический массив строк в пустые объекты. Небольшой private node принимает обычный JSON и использует штатный зашифрованный Telegram credential. Он не требует npm-зависимостей; токен не размещается в workflow, Code или env.

**Как обеспечена изоляция заявок?** Владелец и начальный статус задаются сервером. RLS разрешает чтение и изменение только владельцу, а grants ограничивают изменяемые столбцы. Это проверено обычными сессиями двух пользователей через настоящий Auth/Data API, включая прямые попытки чтения/изменения чужой записи и подмены владельца. Временные пользователи и записи удалены.

**Как защищено сохранение?** Блокировка повторного submit, стабильный UUID попытки, проверка конфликта версии и понятные сообщения об ошибках. Успех подтверждается после ответа сервера.

**Как использован AI?** Для проработки архитектуры, подготовки части кода, SQL, схем и тестов. Результат проверялся сборкой, тестами, реальными запросами к Supabase и Telegram, просмотром интерфейса. Подробности и границы проверок записаны в журнале AI.

**Какие ограничения остались?** Бот рассчитан на личный чат; импорт требует приложенный private node. Повторная доставка Telegram update может дать повторный ответ. Реальная Instagram-интеграция не реализовывалась по условиям задания. Оценка интерфейса на физическом телефоне не заменяется браузерными тестами. Полный список — в README компонентов.
