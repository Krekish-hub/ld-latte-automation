## Что проверено

На **31 октября 2026** приложение опубликовано с мобильной раскладкой и заметным подтверждением создания/сохранения заявки. Пользователь подтвердил регистрацию, получение письма и вход. Пройдены **8 unit-тестов**, локальная SQL-проверка grants/RLS A/B/anon и UI-проверки с **подменённым API**: 320/375/390/414/768px, отсутствие горизонтального переполнения, поиск/фильтр, двойная отправка, редактирование и видимость toast.

Отдельная проверка **живого Supabase Auth/Data API — 23 успешные проверки**: вход двух пользователей по паролю, серверные owner/status, изоляция чтения и изменения, запрет подмены владельца и начального статуса, повторный UUID, собственное редактирование, timestamp/conflict guard, поиск/фильтр, anon и сохранность после повторного входа. Временные пользователи созданы через разрешённый Auth Admin API с подтверждённым email; SMTP не менялся и письма повторно не отправлялись. После проверки независимый запрос подтвердил **0 QA-пользователей и 0 QA-заявок**; временный привилегированный обработчик заменён неактивной версией с ответом 410 и проверкой JWT.

[Отчёт живой A/B-проверки](docs/verification/live-ab-20261031.json) сохраняет исходный `ok=false`: служебная проверка cleanup получила ошибку из-за отсутствия у service_role права SELECT на requests. 23 проверки приложения завершились успешно; очистка отдельно подтверждена SQL, права ради probe не расширялись.

Telegram workflow активен, credentials привязаны; пользователь подтвердил **две кнопки и работающий callback**. Пройдены **39 локальных тестов**, включая цепочку экспортированного Code → фактические expression bindings → отправка JSON-клавиатуры с 0/2/5/9 кнопками. Production webhook работает через прямой HTTPS-вход на порту 88 с проверкой нативного secret header. Для импорта обязателен `CUSTOM.ldLatteTelegram`: код есть в репозитории, токен хранится в штатном зашифрованном Telegram credential n8n, не в workflow/env.

Исследование Instagram объединено с исходниками приложения и бота: схема, план, таблица метрик, проверка этапов и вопросы компании. Дата проверки источников — 30.10.2026. Реальные аккаунты/токены Instagram не подключались: по заданию требуется только план.

Отдельно остаются живые демонстрации меню **0/5/9**, добавления/переименования/отключения услуги и оценка на физическом телефоне. Локальные UI-тесты используют подменённый API; живые A/B-проверки выполнены отдельно через настоящий Supabase Auth/Data API. Повторная независимая проверка доставки email в этот A/B-тест не входила. Подробности и остальные ограничения — [статус приёмки](docs/acceptance-status.md).

## Воспроизвести проверки

Node.js 22.12+ или 24; для frontend нужен pnpm, для UI-тестов — Chromium Playwright. Из корня:

```sh
node --test automation/telegram/tests/logic.test.mjs automation/telegram/tests/custom-node.test.mjs
cd apps/web
pnpm install --frozen-lockfile
pnpm test
pnpm test:sql
pnpm test:ui
pnpm build
```

Для живого запуска сначала примените миграции в `supabase/migrations/` по инструкциям компонентов, настройте Auth и credentials. Повторяемые наборы услуг 0/2/5/9 находятся в `supabase/fixtures/` и меняют только фиксированные демонстрационные UUID. Для полного сценария проверки и порядка настройки используйте README компонентов, а не только команды тестов выше.
